## What is VeryReport?

VeryReport (Chinese name: **非常报表**) is built for common enterprise reporting and analytics needs in China: **Chinese-style complex reports**, **self-service BI**, **data entry / fill**, **ETL**, **data screens**, and **Vera AI natural-language analytics** on one platform—with **SaaS subscription** and **on-premises (private) deployment**.

Typical pain points are not “we cannot build a report,” but:

- Finance / compliance need formal layouts while business needs dashboards—and metrics do not match;  
- After a report is done, users still need to edit cells and write data back;  
- Data must stay on the intranet, yet teams still want to prove value on SaaS first.

VeryReport aims to deliver these capabilities in one product instead of stitching multiple tools together.

```text
Data sources ──▶ ETL / Datasets ──▶ Reports · BI · Fill · Screens · Vera AI
                                      │
                         SaaS trial / On-premises deployment
```

## Why VeryReport

- **Chinese-style complex reports as a first-class capability**: grouping, cross-tabs, parameter queries, form printing, Word / Excel / PDF export  
- **Same data foundation for reports and analytics**: fewer “report metrics ≠ BI metrics” issues  
- **Cell-level fill + form fill**: corrections on the report layout; process collection via forms  
- **Same features on SaaS and on-premises**: validate on trial, then deploy on the intranet when needed  
- **Vera AI**: natural-language Q&A; supports private / local LLMs

## Fit & boundaries

**A good fit when you:**

- Need Chinese-style formal reports + operational analytics with aligned metrics  
- Need cell-level corrections / fill that write back to the database  
- Want SaaS validation first, then private / intranet (incl. localization / “信创”) deployment  
- Want reports, BI, screens, and fill in one product  

**Not a good fit when you:**

- Only analyze a few CSVs personally (desktop tools are lighter)  
- Expect to fork this repo as an open-source engine (there is no source here)  
- Treat VeryReport as a compute engine replacing a data warehouse (queries push down to your databases)
