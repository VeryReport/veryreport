# Architecture（逻辑架构）

> **一句话定义：** VeryReport 将「数据准备 → 语义数据集 → 多形态消费」放在同一产品内：复杂报表、BI、填报、大屏与 Vera AI 共用数据集与权限。  
> **边界：** ① 逻辑视图，非源码结构 ② 不公开内部服务拆分与安装拓扑细节 ③ 操作步骤见 [官网帮助](https://www.veryreport.com/docs?utm_source=github&utm_medium=docs&utm_campaign=developer_hub)。

## 模块边界（选型时常混）

| 模块 | 职责 | 不是什么 |
|------|------|----------|
| **数据集** | 统一语义入口：字段、过滤、权限、供各消费端复用 | 不是数仓本身；不替代 ClickHouse/Doris 等计算引擎 |
| **复杂报表** | 中国式版式、交叉/分组、参数、套打、导出、**格子填报写库** | 不是「只做看板」的 BI；与表单填报是不同入口 |
| **BI 自助分析** | 拖拉拽仪表板、钻取联动、KPI、自助取数 | 不替代正式报送用的固定版式报表 |
| **数据中心表单填报** | 表单设计、任务、审批、入库 | 不等于复杂报表格子订正 |
| **ETL** | 多源清洗、转换、调度，产出可供报表/BI 使用的主题数据 | 不是全功能数据中台替代品的宣传口径 |
| **数据大屏** | 汇报/驾驶舱展示 | 偏展示与刷新，不替代复杂表样 |
| **Vera AI** | 问数 / 解读 / 报告 / 搭建；过程与 SQL 可解释 | **不**对外提供公开 MCP/SDK；见 [`../ai/README.md`](../ai/README.md) |

## 数据流（简化）

1. **接入：** JDBC 类库、文件、API 等（常见 MySQL / Oracle / PostgreSQL / Hive / ClickHouse / Doris 等，以产品内配置为准）。  
2. **准备（可选）：** ETL 加工后再建数据集。  
3. **建模：** 数据集定义口径、计算列、默认过滤。  
4. **消费：** 同一数据集可被报表、BI、大屏、Vera、填报场景引用（按权限）。  
5. **回写：** 复杂报表填报或表单填报将用户输入写回业务库（按填报设置）。

## 权限与 AI

组织、角色与资源权限约束人工查询与 Vera 问数；行列级安全与数据集过滤对 AI 同样生效（与产品设计原则一致）。细节以实现与帮助文档为准。

## 部署形态（架构含义）

| 形态 | 架构含义 |
|------|----------|
| **SaaS** | 多租户云端；数据源经网络连通至租户库 |
| **私有化** | 企业内网部署；数据可不出域；包体与拓扑由交付提供 |

见 [`deployment.md`](./deployment.md)。SaaS 与私有化**功能一致**（产品原则）。
